# 2. Instructions

## Shell commands

Each command runs from this repository's root and never changes directory: a tool that needs a
directory gets it as an argument (e.g. `git -C <dir>`, `cmake -S <dir> -B <dir>`, `npm --prefix <dir>`).
From a parent session, put this repository's path in front of every path in the command. A job marked
*not set up yet* counts as missing, so AGENTS.md rule 2 applies the first time it's needed.

## Tools by action

| Action | Use | Notes |
| --- | --- | --- |
| Read, search, create or edit files | Your built-in file tools | Fix any new diagnostics an edit reports before moving on |
| Run a shell command | `Bash` tool; `PowerShell` where Bash isn't available | Never change directory (`cd`, `pushd`, `Set-Location`): pass directories as arguments. A tool that can only run from its own folder needs its own row here first. Never: interactive commands, `sudo` |
| Find a symbol's definition, references, callers or implementations | `LSP` tool | Search instead only where no language server runs for that file |
| Move, rename or delete files | `git mv`, `git rm` | Ask first for files you didn't create |
| Version control | git CLI | Commit format in [3.CONVENTIONS](3.CONVENTIONS.md#git). Never: push to the default branch, rewrite pushed history, commit secrets or generated files |
| Add a dependency | The project's package manager | Ask first. Pin the exact version. Never: edit lock files by hand |
| Look up external docs | Fetch the official docs for the exact version in use | Never: answer version-specific API questions from memory |

## Playbooks

### Set up from a fresh clone

1. Install the prerequisites in [1.PROJECT](1.PROJECT.md#prerequisites).
2. Setup steps: *not set up yet*. With work repositories, include how to fetch them
   (e.g. `git clone --recurse-submodules`).
3. Check it worked: the Build and Test commands above both succeed.

Known traps: none recorded yet.

### Answer a question or investigate

1. Check the docs index in AGENTS.md first, then the code. Read only; change nothing.
2. Cite `path:line` for every claim about the code.

### Fix a bug

1. Reproduce it as a failing test (AGENTS.md rule 3).
2. Fix the cause, not the symptom, until that test passes. Then finish the task as below.

### Add or change a feature

1. Read `docs/<Feature>/README.md`. For a new feature, copy [the feature template](_FEATURE_TEMPLATE/README.md)
   to `docs/<Feature>/`, add its row to AGENTS.md "Feature docs", and copy its rule to `.claude/rules/<Feature>.md`.
2. Write the failing tests for the new behaviour, then implement.
3. Finish the task as below.

### Rename or restructure

1. Check [6.TODOS](6.TODOS.md) and [5.DECISIONS](5.DECISIONS.md) for an existing plan, or a reason not to.
2. Find every use with the `LSP` tool's references and change each one; move files with `git mv`. The
   existing tests must pass unchanged.
3. Delete the finished TODO, then finish the task as below.

### Sync the docs with the code

Usually run in a fresh session. The user gives a git range; if they don't, use the commits since docs/
last changed (`git log -1 --format=%H -- docs AGENTS.md`).

1. List the changes: `git log --oneline <range>` and `git diff --stat <range>`. Read the diffs that matter.
2. Route each change: commands and tools → 2.INSTRUCTIONS (ask first, per AGENTS.md rule 2); purpose,
   milestones, prerequisites, layout → 1.PROJECT; style, architecture, contracts → 3.CONVENTIONS; test
   layout → 4.TEST; a choice between real alternatives → 5.DECISIONS; deferred work → add to 6.TODOS, and
   delete finished ones; a feature's behaviour → `docs/<Feature>/README.md`.
3. Make the smallest edit that makes each doc true. Describe the present, not history. Write only facts
   you verified. Skip anything the code, a linter or the types already say. Put a fact in the repository
   it is about, and link to it from elsewhere instead of copying it.
4. Check: every doc in `docs/` except `_`-prefixed ones is linked from AGENTS.md, and every link resolves;
   no `{{` placeholders remain outside `docs/_FEATURE_TEMPLATE/`; CLAUDE.md is still `@AGENTS.md`; each
   `.claude/rules/*.md` `paths` still matches real files; `.claude/agents/SUBAGENTS.md` frontmatter is
   valid YAML with a `name` and `description`.
5. Report the files you changed, one line each, and anything you couldn't verify.

### Change a contract with another repository

1. Update the spec in `docs/<Feature>/` and its row in [3.CONVENTIONS](3.CONVENTIONS.md#contracts-with-other-repositories).
2. Change the producer, then every consumer. With work repositories, hand each side to its agent.
   Run each one's tests.
3. Commit in each repository separately.

### Finish any task

1. Run the build, the full test suite and lint (Shell commands above). All must pass.
2. Report what you ran and the result. Note anything left undone as a candidate for 6.TODOS.
