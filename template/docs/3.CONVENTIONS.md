# 3. Conventions

**Scope:** every file.

## Coding standard

**Always** follow Epic's [C++ Coding Standard](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)
for the engine version in use: naming and type prefixes, formatting, `const`, includes, comments, and the rest.
Where it says nothing, match the engine's own code, under `Engine\Source` in the engine's folder.

## Vocabulary

**Always** use these terms in code, comments, logs and docs; **never** a synonym.

None yet.

## Architecture

- **Always** depend one way: game modules on plugins, plugins on the engine. **Never** name the game from a plugin:
  ask through an interface or a settings class.
- **Always** put behaviour that more than one actor needs in a component, not in an actor subclass.

## Errors and logging

- **Never** `check` anything but this code's own invariants. **Always** test and handle what can come from data,
  content or the network, with a log line that says what was refused and why.
- **Always** log through the module's own category (`DECLARE_LOG_CATEGORY_EXTERN`). **Never** use `LogTemp`, and
  **never** log secrets or personal data.

None.
