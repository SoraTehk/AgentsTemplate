# 4. Test

## Test-first loop

1. Write or change the smallest test that states the new behaviour.
2. Run it. It must fail, and for the reason you expect: an assertion, not a compile error or missing file.
3. Implement until it passes, then run the whole suite.
4. Refactor only while the suite stays green.

## What each change ships with

- New or changed behaviour: tests at the lowest layer that owns it.
- Bug fix: a test that reproduces the bug, written before the fix.
- Contract change: a test on each side that pins the contract.

## Writing tests here

- Test data: small, committed, in a `fixtures/` folder beside the tests that use it.
- Fakes: only for what the test doesn't own (network, clock, randomness, file system). Never fake the code
  under test.
- Determinism: no real time, randomness or network in unit tests; inject them.

## Exempt from test-first
