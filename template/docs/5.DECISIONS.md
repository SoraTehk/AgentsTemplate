# 5. Decisions

## D-001: Agent docs follow the AgentsTemplate layout

- **Context:** coding agents need the same instructions every session, in every tool, and in every
  repository of a workspace.
- **Decision:** AGENTS.md is the always-loaded index and enforcement; `docs/1`–`6` hold the detail;
  CLAUDE.md only imports AGENTS.md. Source: [AgentsTemplate](https://github.com/SoraTehk/AgentsTemplate).
- **Rejected:** one long CLAUDE.md, because it costs context on every turn and other agents don't read it.
- **Revisit when:** a tool the team relies on can't read AGENTS.md.

## D-002: A feature is documented like a repository, one level down, and only adds to the root

- **Context:** features share one build, one set of commands, one test setup and one git history, yet each grows
  facts, rules and decisions of its own.
- **Decision:** `docs/<Feature>/README.md` is the feature's index, as AGENTS.md is the repository's, and
  `.claude/rules/<Feature>.md` loads it, as CLAUDE.md loads AGENTS.md. Its numbered docs add to the root doc with the
  same number and never override it. One exists only once the feature has something of its own for it. Another
  feature relies only on the README's Contract. Features don't nest: a big one splits into sibling features.
- **Rejected:** a work repository per feature, which splits one build and one session across agents; one README per
  feature, which large features outgrow; every numbered doc in every feature, which fills folders with "see the root".
- **Revisit when:** a feature needs its own build or release cycle: make it a work repository.
